# Certifying retrieval policies with non-neutral AI judges — code, results and pre-registration record

Research artifact for the manuscript *Certifying Retrieval Policies with Non-Neutral AI Judges: What a Judge Saves, and How a
Pilot Predicts It* (under review at TMLR). Every number in the paper is regenerated from the row-level result files under
`04_results/` by the scripts under `03_code/`; the lock documents under `02_data/` and the log in `04_results/heldout/LOCK_NOTE.md`
are the pre-registration record (see the section below for what the commit history does and does not show).

## Layout
| Path | Content |
|---|---|
| `01_design/` | Development log (design, every negative result, retraction and post-hoc change) and the menu-allocation exploration note |
| `02_data/` | Pre-registration locks v0.4–v0.7, the ε = 0.03 pilot-sweep prediction record, and the archived manifest of the initial release |
| `03_code/lib/` | `certificates.py` (split / PPI++ certificates, finite-population and betting bounds), `neutrality.py` (ρ bounds), `design.py` (menu allocation), `costpredict.py` (pilot-based cost predictors v1–v4), `ledger.py` (unique-label accounting), `figstyle.py` |
| `03_code/6x_*.py` | Pool builders (BEIR stacks; fully judged pools for TREC DL, CAsT 2019, ANTIQUE, NeuCLIRBench) and LLM judges |
| `03_code/63, 67, 70, 72, 77` | Sequential certificates, PPI gain, neutrality diagnostic, self-preference test, mechanism map |
| `03_code/80–83` | Document-level auditing: decision-weight sampling, judge control variates, sampling baselines (incl. `uniform_nz`), active inference, menu allocation |
| `03_code/84–88` | Unified metrics, Table 2 (`86`), exact-certificate table, pilot-size sweep |
| `03_code/93–99` | Figure F4, bootstrap intervals (`94`), variance-dilution cost model (`95`), certificate calculator (`96`), pre-audit rule (`97`), locked predictions (`98`), all figures (`99`) |
| `03_code/RUN_*.sh` | Grids: revised accounting, Track C (`--dump_draws`), NeuCLIRBench lock pipeline |
| `04_results/` | Row-level results per experiment; `unified/` tables and cost-model outputs; `heldout/` locked predictions, scores and the lock note |
| `05_paper/tmlr_submission/` | LaTeX source, figures and compiled PDF; `05_paper/THEORY_v0.1.md` propositions and proofs; `05_paper/make_supplementary.sh` builds the anonymous supplementary zip |

Two kinds of row-level records are kept out of the tree because of their size and are shipped as two archives (`release/draw_records.tar.gz`,
42 MB, and `release/locked_predict_records.tar.gz`, 48 MB, both included in the supplementary zip; also attached as release assets of the
repository): the per-draw audit records (`*_draws.csv`; regenerated by `81_sampling_baselines.py --dump_draws`, needed by `94_j50_ci.py`
and `97_pilot_rule.py`) and the pilot-only prediction records that were committed as locks before each audit (`*_predict.csv`; their lock
commits remain in the history, and the derived `04_results/heldout/PREDICTIONS_*` files stay in the tree). Extract both archives into
`04_results/` (`tar xzf release/draw_records.tar.gz -C 04_results`, likewise for the second). The outputs of the two scripts that need them
(`04_results/unified/J50_CI_*.csv`, `PILOT_RULE_*.csv`, `04_results/heldout/PILOT_RULE_*.csv`) are committed, so every table and figure
regenerates without the archives; the archives are needed only to recompute those outputs from the draw level.

## Reproduction
Requirements: Python 3.11 and the pinned packages in `requirements.txt` (`pip install -r requirements.txt`: numpy, pandas, scipy,
scikit-learn, matplotlib, pyarrow; pyarrow reads the Parquet files under `04_results/planner_v2` and `04_results/primary_*`). Building
pools and running judges additionally needs torch, `transformers==4.51.3`, `sentence-transformers==3.4.1`, bm25s and one 24 GB GPU.
Run grids with one BLAS thread per process (`OMP_NUM_THREADS=1`); the run scripts do this and cap concurrency at the CPU quota.

- Pools: `61_build_pool.py` (BEIR), `64/75/87/89/100` (fully judged pools). Judges: `66_llm_judge.py <name> --cand <dir> --texts ... --queries ...`.
- Tables and figures from the committed results: `python3 03_code/86_table2_v2.py v3`, `python3 03_code/95_cost_model.py`,
  `python3 03_code/96_ppi_calculator.py`, `python3 03_code/93_plot_F4.py`, `python3 03_code/99_figures.py`.
- Fixed-budget grid with per-draw records: `03_code/RUN_TRACK_C.sh`; the NeuCLIRBench locked test: `03_code/RUN_NEUCLIR.sh {pool|judge|predict|audit}`.
- Paper: `cd 05_paper/tmlr_submission && pdflatex main && bibtex main && pdflatex main && pdflatex main`.

## Candidate pools (`pools_bundle`)
The audit experiments (`63`, `67`, `70`, `72`, `77`, `80`–`83`, `86_f1_weighted`, `88_cast_report`, `91`) read a pools bundle, which is
distributed separately from the tree: the pooled document texts inherit the licences of the source collections and are not
redistributed, and the pool CSVs are large. During review the bundle without texts (every file the analysis scripts read) can be
obtained through the Action Editor; on acceptance it is published with the repository. Its layout, verified by
`92_pools_manifest.py verify <bundle>` against the shipped `MANIFEST.csv`, is

```
<pools_bundle>/<stack>/runs/candidates/<name>.csv          one row per pooled (query, document) pair
<pools_bundle>/<stack>/runs/candidates/<name>_meta.csv     qid, nG (relevant documents), n_judged
<pools_bundle>/<stack>/runs/candidates/<name>_llm.csv      Qwen3-8B judge: qid, docid, llm_grade, llm_p_rel   (66_llm_judge.py)
<pools_bundle>/<stack>/runs/candidates/<name>_mistral.csv  Mistral-7B judge, same columns                     (66 --model)
<pools_bundle>/<stack>/runs/candidates/<name>_mpnet.csv    MPNet rank rule: qid, docid, mpnet_cos, mpnet_p_rel (73_mpnet_judge.py)
```
with stacks `legacy` and `modern` (BEIR development pools: nfcorpus, scifact, arguana, cqadupstack-android, plus the BEIR targets),
`judged` (fully judged pools: dl2019, dl2020, trec-covid, webis-touche2020, dbpedia-entity, dl212223, cast19, antique) and
`neuclir` (neuclir_eng). Pool rows carry `qid, docid, score_norm, rank, consensus, lexoverlap, in_bm25top10, judged, grade, relevant,
qwen3e_cos, rr_yes`; the reranker judge and the inverted judge are the `rr_yes` column and its complement, so they need no side file.
Scripts take the bundle as `--pools <pools_bundle> --stack <stack> --names <name ...>` and the BEIR training pools as
`--train_dir <pools_bundle>/legacy/runs/candidates`.

To rebuild the bundle from the source collections (GPU): `61_build_pool.py` for the BEIR stacks, `64_trecdl_pool.py`, `75_dlv2_pool.py`,
`87_cast_pool.py`, `89_antique_pool.py` and `100_neuclir_pool.py` for the fully judged pools (each takes the collection's qrels and
texts and writes `<stack>/runs/candidates/`), then `66_llm_judge.py <name> --cand <candidates dir> --texts <docid\ttext tsv> --queries
<qid\ttext tsv>` for the LLM judges and `73_mpnet_judge.py` for the MPNet rule; `RUN_NEUCLIR.sh pool` and `RUN_NEUCLIR.sh judge` show the
exact invocations for one collection.

## Pre-registration record
`02_data/PROSPECTIVE_LOCK_v0.4–v0.6` govern the three external evaluations of the paper; `PROSPECTIVE_LOCK_v0.7` governs the
NeuCLIRBench test of the pre-audit rule. `04_results/heldout/LOCK_NOTE.md` lists, in order, every lock commit, every audit, the
one formula bug found in a lock, and which predictors were fixed before or after which audit. Nothing in that note is edited
after the fact except to append.

What the commit history shows: the held-out prediction locks (`54deba0`, `694e00b`) and the NeuCLIRBench lock v0.7 (`1750865` text,
`b833065` / `ad91bfd` predictions) are separate commits that precede the audits they govern. What it does not show: the locks v0.4–v0.6
entered this repository in its first commit together with their results (they were written in the private development repository
before the target data were accessed), and the history was rewritten once for attribution, so commit timestamps are not independent
evidence of timing. Readers who need such evidence should treat the pre-registration as self-reported.

Pilot-rule scores: `04_results/unified/PILOT_RULE_eps*.csv` and `PILOT_RULE_single_eps*.csv` (development collections) and
`04_results/heldout/PILOT_RULE_single_{llm,rr}_{ho,ho10}_eps*.csv` (TREC-COVID / Touché) are the outputs of `97_pilot_rule.py` on the
release draw records; they are committed so that Table 4 and the in-text rule numbers can be checked without the release assets.
